Take the list in scope — open questions, todos, line items, review findings, anything
needing a series of decisions from me — and walk it **one item at a time**, getting my
call on each before moving to the next.

If no list is named, ask which list. $ARGUMENTS

## How to ask each item
- **One at a time.** Ask a single item, wait for my answer, then move on. Never batch.
- **Short.** 2-3 lines per question, like `/s`. Lead with the decision to be made.
- **No jargon.** Plain language. If a term is unavoidable, define it in a half-line.
- **Give options + a recommendation.** Offer the concrete choices (A/B/C), mark the one
  you'd pick, and one clause on why. If a question can be answered by reading the
  codebase, do that instead of asking me.
- **No preamble, no next-steps padding.** Just the question.

## After each answer
- Record the decision where it belongs (the ticket file, todo list, etc.) before asking
  the next — rewrite the item in place; log an overturned belief rather than deleting it.
- If my answer changes a later item, say so when you reach it.

## Finish
When the list is exhausted, give a tight recap: each item → the decision made.
